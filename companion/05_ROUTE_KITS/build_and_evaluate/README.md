# CREATE — Build-and-evaluate

**Locked route meaning:** Can a designed artefact address a bounded problem?  
**Minimum planning evidence:** Requirements, rationale, accepted tests and evaluation criteria.  
**Immediate warning:** Technology list; evaluation deferred.  
**Claim boundary:** Local demonstration becomes production or institutional readiness

Use `ROUTE_GATE_PLAN.csv` to see what evidence the common nine-gate chain requires for this route. Use `ROUTE_RECORD_SELECTION.csv` to select shared templates and `RISK_AND_BOUNDARY_REGISTER.csv` to preserve the principal failure signatures. The `worked_example` folder is synthetic and schema-aligned. It is a teaching object, not an empirical result or a substitute for an approved project protocol.

## Demonstration lens

Execute one valid path, one rejected duplicate and one interrupted recovery from the frozen release, then retrieve the audit record.

## Hostile defence lens

**Question:** Why does a successful laboratory prototype justify any deployment claim?  
**Bounded answer:** It does not. The evidence supports only the tested behaviour under the declared synthetic tasks and identifies unresolved deployment, security and accessibility obligations.
